# GitHub Export (Branch / PR / Issues)

GitHub export **reuses the existing export bundle** — there is no second export code path. The
same files the ZIP would contain are committed into a repo branch.

## Where the file list comes from

`lib/export/bundle.ts` exposes `collectExportFiles(ctx, modes)` — a pure function (no JSZip, no
`file-saver`) returning `{ files: ExportFile[], manifest, slug }`. Both paths use it:

- **Download ZIP** → `createExportBundle` zips those files.
- **GitHub** → `POST /api/github/export` maps those files under the destination path and commits
  them.

## Export → GitHub flow (`/api/github/export`)

1. Validate session + connection + repo ownership (`getGitHubContext` / `clientForRepo`).
2. Validate the posted pipeline through Zod; derive `productDrop` / `realityMeter` if absent.
3. `collectExportFiles(ctx, modes)` builds the file list + manifest (with health check).
4. **Export safety check** (`scanExportFilesForSecrets`) — if anything looks like a secret, the
   request is rejected (422) before any write.
5. Create the branch off the chosen base (versioned if the name already exists).
6. Commit each file under `destinationPath`. If a file already exists, the default
   `onConflict: "version"` writes it under a `…-v2` path — **repo files are never silently
   overwritten**.
7. Optionally open a PR with a generated description.
8. Persist a `GitHubExportResult` to `github_exports` (best-effort).

## Destination folder

The Export dialog offers presets (`flowmind/<slug>`, `src/ai/<slug>`, `lib/flowmind/<slug>`,
`app/api/ai/<slug>`) and a custom path. The **file-placement assistant** (`lib/github/fileTree.ts`)
reads the repo's top-level entries via
`/api/github/repositories/[owner]/[repo]/tree` and suggests a path based on detected signals
(`next.config.*`, `src/`, `app/`, `pnpm-workspace.yaml`, `turbo.json`, …).

## PR description

`generatePullRequestBody` (`lib/github/pullRequests.ts`) builds the body from Flowmind data:

- Product name + pitch
- What the PR adds (nodes, crews, tools, datasets, runtime, docs)
- How to run + **required env var names** (never values)
- Sources & integrations
- Missing pieces
- Reality Meter (score, hardest part, fastest MVP)
- Next-steps checklist
- "Generated by Flowmind" note

No secret values appear — env vars are listed by **name** only.

## Implementation issues (`/api/github/create-issues`)

`generateIssueDrafts` turns the Reality Meter + export health check + data-contract warnings into
issue drafts:

- Wire missing APIs / adapters
- Add missing env vars
- Fix failing/warning data contracts
- Add missing UI bindings
- Add an evaluator
- Resolve export-health warnings

Each draft has context, expected output, and acceptance criteria. The UI previews drafts, lets you
select/deselect, pick a repo, and create the selected issues. Default labels: `flowmind`,
`ai-pipeline`, plus a per-category label (`integration`, `env`, `data-contract`, `ui`, `export`).

## UI

Export dialog → **Push to GitHub** / **Create PR** tabs (`components/github/GitHubExportPanel.tsx`):
repo selector, base/new branch, destination path (+ presets), a preview line, a push button, and an
**Issues** button. Success state shows the branch URL, PR URL/number, files-changed count, and a
copy-PR-link button.

## Public-demo behavior

Unauthenticated users can still use the builder and ZIP export, but GitHub connect/push prompts them
to sign in. Normal ZIP export is never blocked.
